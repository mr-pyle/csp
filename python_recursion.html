3. Why Python Avoids Tail-Call Optimization (TCO)
Design Philosophy

How Python Works: Keeps Every Stack Frame

Suppose a bug happens when n = 0 (like dividing by n). Because Python keeps every frame on the stack, it prints a full Error Traceback showing every step that led to the crash:

Frame 1: bug_demo(3)line 4 → called bug_demo(2)
Frame 2: bug_demo(2)line 4 → called bug_demo(1)
Frame 3: bug_demo(1)line 4 → called bug_demo(0)
Frame 4: bug_demo(0)ZeroDivisionError at line 2!

Result: Easy to debug! You can trace the exact path of calls.

Tail-Call Optimization (TCO): Overwrites Frames

Languages with TCO recycle the same single frame in memory to avoid stack limits. However, when n = 0 crashes, all earlier call history has been erased:

Frame 1: bug_demo(3)[Overwritten in memory]
Frame 2: bug_demo(2)[Overwritten in memory]
Frame 3: bug_demo(1)[Overwritten in memory]
Active Frame: bug_demo(0)ZeroDivisionError (Where did 0 come from?!)

Python's creator (Guido van Rossum) chose readable tracebacks and clear for/while loops over TCO.
